# Open Source Solutions Evaluation Criteria

오픈소스 서비스/솔루션을 평가할 때 사용하는 기준.

---

## 핵심 질문

> "이 오픈소스를 써도 괜찮을까?"

판단 기준:
1. 아직 관리되고 있나? (활성도)
2. 많은 사람이 쓰고 있나? (검증)
3. 문서가 잘 되어 있나? (사용성)
4. 라이선스가 맞나? (법적 문제)
5. 우리 스택과 맞나? (기술 호환성)

---

## 필수 체크 항목

### 1. 활성도 (Activity) - 가장 중요!

| 지표 | 좋음 | 주의 | 위험 |
|-----|------|------|------|
| 마지막 커밋 | 1개월 이내 | 3-6개월 | 1년 이상 |
| 이슈 응답 | 1주 이내 | 1개월 | 응답 없음 |
| 릴리즈 주기 | 정기적 | 불규칙 | 멈춤 |
| 오픈 이슈 처리 | 활발히 처리 | 쌓여있음 | 방치 |

**비개발자 설명:**
> "가게 주인이 매일 출근하는지 확인하는 거예요. 방치된 가게에서 물건 사면 AS 못 받잖아요. 마찬가지로 관리 안 되는 오픈소스는 문제 생겨도 도움받기 어려워요."

### 2. 검증도 (Popularity)

| 지표 | 의미 | 기준 |
|-----|------|------|
| GitHub Stars | 관심도/품질 지표 | 1,000+ 권장 |
| 사용 기업 | 실제 프로덕션 검증 | 유명 기업 사용 시 신뢰 |
| 커뮤니티 크기 | 문제 해결 가능성 | Discord/Slack 활성도 |

**비개발자 설명:**
> "맛집 평점 같은 거예요. 별이 많으면 많은 사람이 써봤고 괜찮다는 뜻이에요."

**Stars 기준:**
- 10,000+ : 매우 검증됨 (안심하고 사용)
- 5,000-10,000 : 검증됨 (추천)
- 1,000-5,000 : 적당히 알려짐 (주의하며 사용)
- 1,000 미만 : 검증 부족 (특별한 이유 없으면 비추천)

### 3. 문서화 (Documentation)

체크리스트:
- [ ] 공식 문서 사이트 존재
- [ ] 설치/시작 가이드 (Getting Started)
- [ ] API 레퍼런스
- [ ] 예제/튜토리얼
- [ ] 배포 가이드 (Self-hosting guide)
- [ ] 한국어 문서 (보너스)

**비개발자 설명:**
> "이케아 가구 설명서 같은 거예요. 설명서 없이 복잡한 가구 조립하면 힘들잖아요."

### 4. 라이선스 (License)

| 라이선스 | 상업적 사용 | 코드 공개 | 주의사항 |
|---------|------------|---------|---------|
| MIT | OK | 불필요 | 가장 자유로움 |
| Apache 2.0 | OK | 불필요 | 특허 보호 포함 |
| BSD | OK | 불필요 | MIT와 유사 |
| LGPL | OK | 수정분만 | 라이브러리로 사용 시 OK |
| GPL | 조건부 | 필요 | 전체 코드 공개 필요! |
| AGPL | 조건부 | 필요 | 서버 운영만 해도 공개! |
| BSL | 조건 확인 | 기간별 | 상업적 제한 기간 있음 |

**비개발자 설명:**
> "저작권 같은 거예요. MIT/Apache는 '마음대로 쓰세요', GPL은 '쓰려면 조건이 있어요'예요."

**상업용 프로젝트라면:**
- MIT, Apache 2.0, BSD → 안전
- GPL, AGPL → 주의! 코드 공개 의무
- BSL → 조건 꼼꼼히 확인

### 5. 기술 스택 호환성

확인 사항:
- 우리 기술 스택과 맞는가? (React 프로젝트에 React 기반 오픈소스)
- 의존성이 최신인가? (오래된 Node.js 버전 요구 등)
- 통합이 쉬운가? (API, SDK 제공 여부)

## Red Flags (위험 신호)

**즉시 제외해야 할 경우:**

- 1년 이상 업데이트 없음 (안정화된 라이브러리 제외)
- 메인테이너 1명 + 활동 없음
- 보안 취약점 미해결 (Snyk 등에서 확인)
- 문서 없음 또는 극히 부실
- GPL/AGPL인데 상업용 프로젝트
- 오픈 이슈 수백 개 방치
- 마지막 릴리즈 2년 이상 전

**비개발자 설명:**
> "이런 신호가 보이면 위험해요. 문 닫은 가게에서 물건 사면 환불도 못 받고, 고장나면 수리도 못 받아요."

## 평가 템플릿

### 간단 평가 (Quick Check)

```markdown
### [프로젝트명] 빠른 평가

| 항목 | 상태 | 비고 |
|-----|------|------|
| Stars | ⭐⭐⭐ | 15k stars |
| 최근 커밋 | 2일 전 | 활발함 |
| 문서화 | 공식 문서 있음 | 영어 |
| 라이선스 | MIT | 상업용 OK |

**결론:** 사용 추천 / 주의 필요 / 비추천
```

## 비교 평가 시 팁

### 1. 동일 카테고리끼리 비교

- Medusa vs Saleor vs Vendure (이커머스)
- Strapi vs Payload vs Directus (CMS)
- Rocket.Chat vs Mattermost vs Zulip (채팅)

### 2. 프로젝트 상황 고려

| 상황 | 우선순위 |
|-----|---------|
| 빠른 출시 필요 | 문서화 > 기능 수 |
| 장기 운영 | 활성도 > 인기도 |
| 상업용 | 라이선스 > 기능 |
| 학습용 | 문서화 > 라이선스 |

### 3. 숨은 비용 고려

- Self-hosted 운영 비용 (서버, 관리)
- 커스터마이징 비용 (개발 시간)
- 마이그레이션 비용 (나중에 바꾸려면)
- 학습 비용 (팀이 배우는 시간)
